# Тестирование веб-приложения «Яндекс.Маршруты»

Этот проект — моя учебная работа по ручному тестированию. Я проанализировала требования, составила тестовую документацию и проверила работу сервиса.

---

## 🎯 Что тестировалось
**Объект:** Веб-приложение для построения маршрутов (предположительно, с расчетом времени и стоимости).
**Задача:** Проверить функциональность, UI и обработку ошибок на основе предоставленной документации.

---

## 📋 Что было сделано
1.  **Анализ требований** — изучила макет в Figma и описание функционала.
2.  **Составление тестовой документации:**
    *   **Чек-лист для верстки (Каршеринг/Тариф Роскошный)** — 61 пункт.
    *   **Чек-лист для функционала (Способ оплаты и Добавление карты)** — 39 пунктов.
    *   **Тест-кейсы для кнопки «Забронировать»** — 5 детальных сценариев.
3.  **Выполнение тестирования:**
    *   Провела ручные прогоны тестов.
    *   **Баг-репорты** — описала все найденные проблемы.


---

## 🔍 Использованные техники тест-дизайна
Для лучшего покрытия я применила:
*   **Классы эквивалентности** — чтобы разбить все возможные входные данные на группы.
*   **Граничные значения** — чтобы проверить поведение системы на границах допустимых значений.
*   **Предугадывание ошибок** — чтобы найти скрытые проблемы, основываясь на типичных ошибках в таких сервисах.

---

## 📈 Результаты
*   **Всего написано:** 105 тестов (61 чек-лист по вёрстке + 39 чек-листов по функционалу + 5 тест-кейсов).
*   **Найдено багов:** 39.
    *   🔴 **7 блокирующих** — ошибки, которые полностью останавливают работу (например, невозможность завершить бронирование).
    *   🟠 **14 критических** — проблемы с ключевым функционалом (неверный расчёт стоимости, ошибки в логике).
    *   🟡 **4 стандартных** — незначительные баги, не влияющие на основной сценарий.
    *   🟢 **15 желательных** — мелкие недочёты, которые можно исправить в следующих версиях.
*   **Самые частые проблемы:** ошибки валидации полей и некорректное отображение цен при смене тарифа.
