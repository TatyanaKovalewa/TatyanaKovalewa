# BUG4 — Не появляется сообщение «Заказ оформлен» при нажатии кнопки «Да» в окне подтверждения заказа в браузере Chrome

| | |
|---|---|
| **Приоритет** | ⚫ Блокирующий |
| **Компонент** | Веб-интерфейс · Оформление заказа · окно «Хотите оформить заказ?» |
| **Браузер** | Google Chrome 151.0.7922.173, режим headless |
| **Окружение** | Сайт qa-scooter.praktikum-services.ru; ОС Ubuntu; Selenium WebDriver 4.27.0; разрешение окна 1920×1080 |
| **Не воспроизводится** | Mozilla Firefox 154.0 — тот же сценарий на тех же данных проходит успешно |
| **Дата проверки** | 26.08.2026 |
| **Статус** | Открыт, воспроизводится стабильно |

## Описание

В Chrome нажатие «Да» в окне подтверждения заказа не приводит ни к чему: окно остаётся открытым, сообщение «Заказ оформлен» не появляется, **на сервер не уходит ни одного запроса**.

В Firefox тот же сценарий, те же тестовые данные и те же локаторы отрабатывают корректно — заказ создаётся.

Затронут основной пользовательский сценарий сервиса в браузере с наибольшей долей рынка.

## Шаги воспроизведения

1. Открыть `https://qa-scooter.praktikum-services.ru/` в Chrome
2. Закрыть баннер cookie
3. Нажать «Заказать»
4. Заполнить форму «Для кого самокат»: имя, фамилия, адрес, станция метро (выбрать из выпадающего списка), телефон → «Далее»
5. Заполнить форму «Про аренду»: дата доставки, срок аренды, цвет, комментарий → «Заказать»
6. В окне «Хотите оформить заказ?» нажать «Да»

## Ожидаемый результат

Окно закрывается, появляется сообщение «Заказ оформлен» с номером заказа.

## Фактический результат

Окно «Хотите оформить заказ?» остаётся на экране. Сообщения об успехе нет, сообщения об ошибке тоже нет. Заказ не создан.

## Доказательства

Разбор в Chrome — что проверялось и что получилось:

| Проверка | Результат |
|---|---|
| Обе формы заполнены | ✅ все поля, включая станцию метро и дату (значения считаны из DOM) |
| Окно подтверждения открылось | ✅ |
| Кнопка «Да» — единственная, видимая, активная | ✅ |
| Клик мышью | ✅ выполняется без исключений |
| Клик через JavaScript | ✅ выполняется, результат тот же |
| Ошибки в консоли браузера | нет |
| **Сетевые запросы после нажатия «Да»** | **ни одного** |

Сетевая активность снималась через CDP (`Network.requestWillBeSent`), буфер сбрасывался непосредственно перед кликом. За 3 секунды после нажатия не зафиксировано ни одного запроса — то есть `POST /api/v1/orders` не отправляется.

Контрольный прогон того же сценария в Firefox 154.0: **заказ создаётся, тест проходит.**

## Проверенные и отвергнутые гипотезы

| Гипотеза | Как проверялась | Итог |
|---|---|---|
| Кнопку перекрывает баннер cookie | Баннер закрывается до начала сценария | ❌ не подтвердилась |
| Клик промахивается мимо кнопки | Клик через JavaScript напрямую по элементу | ❌ тот же результат |
| React-датапикер не принял напечатанную дату | Дата выбрана кликом по дню в календаре | ❌ тот же результат |
| Дата доставки в прошлом | Проверено и с прошедшей, и с завтрашней датой | ❌ падает в обоих случаях |
| Сервер не успевает ответить | Ожидание увеличено с 5 до 20 секунд | ❌ тот же результат |
| Ошибка в тестах | Тот же код проходит в Firefox | ❌ не подтвердилась |

## Примечание

Проверка в Chrome с графической оболочкой не выполнялась — в использованном окружении Chrome не запускается под root даже с виртуальным дисплеем. Все наблюдения относятся к headless-режиму Chrome 151.
