# 🐞 Баг-репорты

Дефекты, найденные при автоматизации тестирования учебных сервисов Яндекс.Практикума. Все воспроизведены вручную через curl или Selenium, каждый закрыт автотестом.

Это не разбор упавших тестов, а обратное: тесты написаны по спецификации, а падают там, где ей не соответствует продукт. Поэтому такие тесты не отключены — они продолжают прогоняться в CI и попадать в отчёты, а сборка сверяется со списком уже известных дефектов и краснеет только на новых.

| ID | Название БР | Приоритет | Компонент |
|----|-------------|-----------|-----------|
| [BUG1](./BUG1-login-bez-parolya-504.md) | Ошибка 504 Gateway Timeout через 60 секунд при отправке запроса `POST /api/v1/courier/login` на авторизацию курьера, если не передан пароль | 🔴 Критический | API · Курьеры |
| [BUG2](./BUG2-udalenie-kuriera-bez-id.md) | Ошибка 404 Not Found при отправке запроса `DELETE /api/v1/courier/{id}` на удаление курьера, если не передан id курьера | 🟡 Средний | API · Курьеры |
| [BUG3](./BUG3-prinyatie-zakaza-bez-id.md) | Ошибка 404 Not Found при отправке запроса `PUT /api/v1/orders/accept/{id}` на принятие заказа курьером, если не передан id заказа | 🟡 Средний | API · Заказы |
| [BUG4](./BUG4-zakaz-ne-oformlyaetsya-v-chrome.md) | Не появляется сообщение «Заказ оформлен» при нажатии кнопки «Да» в окне подтверждения заказа в браузере Chrome | ⚫ Блокирующий | UI · Оформление заказа |

## Как это проверялось

**BUG1, Б2, Б3** — прямыми запросами к API. В каждом отчёте приведены не только запрос с дефектом, но и контрольные запросы: они показывают, что сервер умеет отвечать правильно в соседних случаях, и отсекают возражение «так задумано».

**BUG4** — разбором в браузере: значения полей считаны из DOM, сетевая активность снята через CDP, проверены и отвергнуты шесть гипотез. Решающий аргумент — тот же код проходит в Firefox.
