# BUG2 — Ошибка 404 Not Found при отправке запроса DELETE /api/v1/courier/{id} на удаление курьера, если не передан id курьера

| | |
|---|---|
| **Приоритет** | 🟡 Стандартный |
| **Компонент** | API · Курьеры · `DELETE /api/v1/courier/:id` |
| **Окружение** | Учебный стенд `qa-scooter.praktikum-services.ru`, проверено через curl и REST Assured |
| **Дата проверки** | 26.08.2026 |
| **Статус** | Открыт, воспроизводится стабильно |

## Описание

Запрос на удаление курьера без обязательного `id` возвращает `404 Not Found.` — это ответ маршрутизатора о том, что такого маршрута нет. По спецификации ожидается `400` с сообщением о нехватке данных.

Разница существенная: клиент не может отличить «я не передал обязательный параметр» от «такого курьера не существует», потому что оба случая приходят с кодом 404, но с разными сообщениями — и одно из них общее, без указания причины.

## Шаги воспроизведения

1. Отправить `DELETE /api/v1/courier/` с заголовком `Content-Type: application/json`, без указания id

## Ожидаемый результат

`400 Bad Request` с сообщением `Недостаточно данных для удаления курьера`.

## Фактический результат

`404 Not Found` с телом `{"code":404,"message":"Not Found."}`.

## Доказательства

| Запрос | Код | Ответ |
|---|---|---|
| `DELETE /api/v1/courier/` — без id | **404** | `{"code":404,"message":"Not Found."}` |
| `DELETE /api/v1/courier/2147483647` — несуществующий id | 404 | `{"code":404,"message":"Курьера с таким id нет."}` |

Вторая строка — контрольная, она отрабатывает корректно. Сообщение `Not Found.` в первой строке — стандартный ответ маршрутизатора, а не бизнес-логики: случай отсутствующего id просто не доходит до обработчика.

## Влияние

Клиент получает недиагностируемую ошибку: по коду и сообщению нельзя понять, что именно не так с запросом. Для интеграций это означает лишний цикл разбора на стороне потребителя API.
